# Working Rules

## Who you are working with
The owner is a non-coder. Explain in plain language. End every reply with the exact next action.

## Public repo rules
- No future business plans, monetisation ideas, or large-project ideas in any file.
- No secrets, API keys, or personal data in any file.
- Do not change `LICENSE` (AGPL-3.0).
- `.kiro` must never be in `.gitignore`. Check this whenever `.gitignore` changes. If no `.gitignore` exists, only create one for standard build folders.

## How to work
- Work in small steps. After each step, test it and tell the owner exactly how it was verified. If it is unverified, it is not finished.
- Save credits: ask before anything large. No unrequested exploring or refactoring.
- If something fails twice, stop and explain.
- Ask the owner at most 2 short questions at a time, and only if needed.
- Ask before choosing any framework or adding any dependency.

## Agent ownership
Each agent owns separate files and items so agents never edit the same thing. Locked items are never overwritten.

## Logging
Add one entry per session to `KIRO_LOG.md` with: date; Kiro app used (Web/IDE); Kiro feature used (steering, spec, hook, MCP, custom agent) and why; result; how it was verified; a line `Credits used: ___` for the owner to fill in; next step.

## HACKATHON MODE
Hackathon-only items (demo scope, sample mode, judging rules, deadlines) go under a "HACKATHON MODE" heading in each steering file, never mixed into the general rules.
