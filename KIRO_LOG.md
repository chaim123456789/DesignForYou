- **Kiro app used:** Web
- **Kiro feature used:** Hooks (two) and Custom agents (two), plus Steering (`working-rules.md`: small steps, say how each step was verified, no installs, stop if something fails twice, one pull request). Formats and event names were taken from Kiro's own documentation pages "Hooks", "Hook triggers" and "Custom agents: Configuration reference" on kiro.dev. Why: the project has two rules that are easy to break by accident (the browser copy in `docs/engine/` must match `src/` byte for byte, and nothing secret may be committed), plus a Locked-item rule and a submission list that are worth checking the same way every time.
- **Result:** Four new files in `.kiro/`, each built and checked one at a time with its own commit. Nothing under `src/`, `docs/` or `test/` changed.
  1. Hook "keep engine in sync" (`.kiro/hooks/keep-engine-in-sync.json`, helper `.kiro/hooks/keep-engine-in-sync.mjs`). Trigger `PostToolUse`, matcher on Kiro's file write tools (`fs_write`, `fs_append`, `str_replace`, `delete_file`). When the changed file is under `src/`, it runs `npm run export-engine` and then `node --test test/engine-export.test.js`; for any other file it does nothing. Why `PostToolUse` and not "File Save": the "Hook triggers" page says Kiro Web runs only Prompt Submit, Agent Stop, Session Start, Pre Tool Use and Post Tool Use. So it reacts when Kiro changes a file, not when a person edits one. It cannot loop: the export writes `docs/engine/` with Node, not with a Kiro tool, and a guard setting stops a nested run. Why it helps: the web page runs the copies in `docs/engine/`, so a change to `src/` that is not exported would make the page and the tests run different code.
  2. Hook "no secrets before you stop" (`.kiro/hooks/no-secrets-before-you-stop.json`). Trigger `Stop` ("Agent Stop" in the docs). Runs only `node --test test/no-secrets.test.js`, with all its output sent to the error stream, because on a Stop hook Kiro reads normal output as a "stop decision". A pass adds nothing; a failure exits non-zero and Kiro hands the findings to the agent. Kiro runs Stop hooks once per turn, so it cannot loop. Why it helps: the repo is public, and this catches a planted key before the turn ends.
